# One-Page Proposal Writer

A proposal wins when the reader can say yes in one sitting. One page forces the thinking to be sharp.

## Steps

1. Open with the client's problem in their words: the cost or risk of the status quo, quantified if any data exists ("manual reconciliation costs ~6 staff-hours weekly"). Never open with your own company history.
2. State the outcome you propose as a result, not an activity: "reduce reconciliation to under 1 hour weekly" — not "we will implement software".
3. Describe the approach in 3-5 numbered steps with durations; name what changes for the client's team at each step (who does what).
4. Add proof selectively: one relevant case or metric per claim. No proof available? Say what will be verified early instead ("first-week pilot shows baseline numbers").
5. Present terms clearly: price, timeline, what is included, what is not, payment schedule. Vague scope now becomes a dispute later — list exclusions explicitly.
6. Handle the obvious objection in one line (the "what if" the client is already thinking).
7. End with a single decision request and a date: "Reply approved by Friday to start Monday". Offer exactly one alternative if useful (smaller pilot), never a menu.
8. Ruthlessly cut to one page: move detail to an appendix on request. Proposals get longer during editing only if a claim needs evidence.

## Checks

- Problem, outcome, and ask all appear in the first five lines.
- Scope, exclusions, and price are unambiguous.
