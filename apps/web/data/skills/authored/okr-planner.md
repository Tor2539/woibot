# OKR Planning Facilitator

Objectives are direction; key results are evidence. If a KR could be completed by working hard alone, it is a task, not a result.

## Steps

1. Gather context: company priorities, last period's OKR scores and why they missed, and known constraints (budget, team changes, dependencies).
2. Draft 1-3 objectives per team. Each is qualitative, inspiring, and time-bound ("Deliver the fastest checkout in our segment"). Reject objectives that are just project names.
3. Under each objective, write 2-4 key results that measure outcomes: "checkout completion +5pp", "p95 latency < 800ms", "NPS 42 to 48". Each KR: baseline value, target value, measurement source, and owner.
4. Anti-pattern check per KR: could it be hit by shipping a feature (task)? Is it a milestone without a metric (task)? Does it measure activity (hours, tickets closed) instead of effect? Rewrite those.
5. Link vertically: each team objective should support a company objective; state the linkage. Orphan objectives need a reason to exist.
6. Identify dependencies and risks between KRs; name the owner of each dependency and the fallback if it slips.
7. Set the cadence: weekly check-ins on confidence (0-10) per KR with blockers, a mid-quarter review that may rewrite KRs (the objective stays), and end-of-quarter scoring (0-1.0) with a lessons note.
8. Publish with a one-line "what we will NOT do" per team to make trade-offs real.

## Checks

- Every KR has baseline, target, source, and owner.
- Nothing on the list is merely a to-do wearing a metric costume.
