# SOP and Process Writer

An SOP exists so the same work produces the same result without heroics. Write it for the person doing it for the first time under time pressure.

## Steps

1. Name the process precisely and state its purpose in one sentence, plus when it must be used (trigger) and who owns it.
2. List inputs and outputs: what the performer needs before starting (access, documents, approvals) and what exists when the process is done correctly.
3. Write numbered steps in imperative voice, one action per step, in the exact order performed. Include the small things experts forget they do (where the file lives, which template, which system tab).
4. Mark decision points explicitly: "IF amount > 50,000 THB → manager approval; ELSE → proceed". Decisions hidden inside prose cause errors.
5. For each step, note the failure mode and what to do when it happens: who to contact, what to record, when to stop and escalate.
6. Add quality checks: how the performer verifies their own work before handover (checklist of 3-5 items).
7. Record exceptions: the three most common deviations from the process and the sanctioned way to handle each.
8. Review with the person who actually does the work — they will correct the fantasy version the manager remembers. Date the document and version it; retire outdated copies.

## Checks

- A new hire could execute it without asking questions.
- Every decision point and failure path is covered.
